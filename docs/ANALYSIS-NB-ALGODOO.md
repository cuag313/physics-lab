# NB仿真实验 vs Algodoo 深度分析 & 超越计划

## 一、两个标杆的核心实现逻辑

### 1. NOBOOK (NB物理实验) — 教学仿真标杆

**核心理念：器材组装 + 引擎驱动**

| 维度 | 实现方式 |
|------|----------|
| **交互模型** | 拖拽器材 → 放置到光具座/实验台 → 自动连接/对齐 |
| **物理引擎** | 自研分领域引擎（电学引擎、力学引擎、光学引擎），不是通用物理引擎 |
| **光学实现** | 真实光线追踪：从光源发射光线 → 遇到透镜按折射率弯曲 → 到达光屏形成实像 |
| **数据采集** | 实时读数（刻度尺、电流表、电压表），跟随物体移动实时更新 |
| **实验流程** | 引导式步骤 + 自由探索两种模式 |
| **渲染** | 2.5D视角，Canvas2D绘制，拟物化器材外观 |
| **关键优势** | 器材可任意组合，参数可任意调节，像"真正的实验台" |

**NB光学实验的核心逻辑：**
```
1. 光源 → 发出多条光线（扇形/平行）
2. 光线遇到透镜 → 根据薄透镜方程+斯涅尔定律计算折射方向
3. 折射后的光线继续传播 → 遇到光屏汇聚成像
4. 像的大小、正倒、虚实由光线实际汇聚情况决定
5. 移动光源/透镜 → 所有光线实时重算 → 像实时移动
```

### 2. Algodoo — 物理沙盒标杆

**核心理念：万物皆物理对象，所见即所动**

| 维度 | 实现方式 |
|------|----------|
| **交互模型** | 绘制几何体 → 自动赋予物理属性 → 实时模拟 |
| **物理引擎** | 基于变分积分器的多物理场引擎（刚体、流体、弹簧、铰链、光学） |
| **光学实现** | 光线作为物理对象：发射 → 反射/折射 → 可被探测器捕获 |
| **数据采集** | 实时图表：速度、加速度、力的分解，X/Y分量可视化 |
| **场景共享** | Algobox社区，5万+用户创建的场景 |
| **渲染** | 纯2D Canvas，卡通风格，极致流畅 |
| **关键优势** | 实时性极强，物理反馈即时，创意无限 |

**Algodoo光学的核心逻辑：**
```
1. 激光笔/点光源 → 发射光线
2. 光线遇到任何几何体 → 自动检测碰撞点
3. 根据材质属性（折射率、反射率）计算反射/折射
4. 支持全反射、色散、焦散
5. 用户拖动任何物体 → 光线实时重绘
```

## 二、我们的核心差距（逐项诊断）

### ❌ 致命问题

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| 1 | **没有真正的光线追踪** | ★★★★★ | 现有RayTracer.js是简化公式计算，不是从光源逐条发射光线、逐个求交的真追踪 |
| 2 | **没有实时物理循环** | ★★★★★ | 大部分实验是"公式计算+静态渲染"，不是每帧更新的物理模拟 |
| 3 | **不可拖拽** | ★★★★★ | NB和Algodoo的核心体验：鼠标拖动物体，物理实时响应。我们完全没有 |
| 4 | **Three.js渲染开销过大** | ★★★★ | 用WebGL 3D引擎做2D实验，杀鸡用牛刀，性能反而差 |

### ⚠️ 重要问题

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| 5 | **器材不可组装** | ★★★★ | NB的核心：透镜+光屏+光源放在光具座上，可自由移动 |
| 6 | **没有光屏成像** | ★★★ | 凸透镜实验必须有光屏接收光线形成实像 |
| 7 | **光线不连续** | ★★★ | 现在是两条硬编码光线，不是从光源发出的完整光束 |
| 8 | **没有虚像显示** | ★★★ | 虚像应该用虚线延长光线反向汇聚来表示 |

### 💡 改进空间

| # | 问题 | 说明 |
|---|------|------|
| 9 | 没有测量工具 | 刻度尺读数、光屏位置显示 |
| 10 | 没有实验步骤引导 | 教学模式应有的功能 |
| 11 | 没有场景保存/加载 | Algodoo的核心能力 |

## 三、技术路线：融合+超越策略

### 核心决策：Canvas2D为主，放弃Three.js做光学实验

**理由：**
- 光学实验本质上是2D问题（光线在同一平面传播）
- Canvas2D性能远超WebGL（大量线条绘制场景）
- Algodoo就是用2D Canvas做到极致流畅的
- Three.js保留给真正需要3D的实验（原子模型、磁场等）

### 技术架构

```
┌─────────────────────────────────────────────────┐
│                   实验组件层                       │
│  ConvexLensExperiment.jsx (UI + 交互)            │
├─────────────────────────────────────────────────┤
│                   物理引擎层                       │
│  OpticsEngine.js                                  │
│  - 光源（点光源、平行光、激光笔）                    │
│  - 光学元件（透镜、面镜、棱镜）                      │
│  - 光屏（接收成像）                                │
│  - 光线追踪（逐条发射→求交→折射/反射→继续）         │
├─────────────────────────────────────────────────┤
│                   渲染层                           │
│  Canvas2DRenderer.js                              │
│  - 拟物化器材绘制                                  │
│  - 光线绘制（实线/虚线/彩色）                       │
│  - 刻度尺、标注                                    │
│  - 60fps 动画循环                                  │
├─────────────────────────────────────────────────┤
│                   交互层                           │
│  DragManager.js                                   │
│  - 鼠标/触摸拖拽                                   │
│  - 碰突检测（吸附到光具座）                         │
│  - 实时参数更新                                    │
└─────────────────────────────────────────────────┘
```

### 超越点（我们能做到而NB/Algodoo不容易做到的）

1. **Web原生 + 免安装**：NB需要安装，Algodoo需要下载。我们浏览器直接用
2. **AI辅助**：可以集成AI解释实验现象、出题
3. **数据导出**：实验数据可导出CSV/Excel
4. **响应式**：手机/平板/电脑都能用
5. **开源**：可定制、可扩展

## 四、实施计划（以"凸透镜成像"为突破口）

### Phase 1：Canvas2D光学引擎 [核心]
- [ ] OpticsEngine.js：光线类、光源类、光学元件基类
- [ ] 真实光线追踪：逐条发射→求交→折射→继续传播
- [ ] 薄透镜折射：使用近轴近似公式精确计算折射方向
- [ ] 光屏接收：光线到达光屏时计算汇聚点形成像

### Phase 2：拖拽交互系统
- [ ] DragManager.js：统一的拖拽管理

- [ ] 吸附对齐：自动居中对齐
- [ ] 实时反馈：拖动时所有光线实时重绘

### Phase 3：凸透镜成像实验
- [ ] 完整光路：从物体发出的3条特征光线
- [ ] 光屏成像：实像在光屏上显示
- [ ] 虚像处理：虚线延长显示虚像
- [ ] 数据面板：物距、像距、焦距、放大率实时显示
- [ ] 预设场景：5种典型成像情况快速切换

### Phase 4：教学增强
- [ ] 实验步骤引导
- [ ] 知识点弹出
- [ ] 成像规律表格
- [ ] 物距-像距曲线图
