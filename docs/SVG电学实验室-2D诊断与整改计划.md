## 二、2D 设计合理性诊断

### 2.1 合理项（保留）

1. **画布与坐标系**：1800×1100 固定画布 + 40px 网格，元件可拖出边界 ±10px 余量；导线 Verlet 粒子链（18 粒子、12 次松弛、重力下垂）形态由物理决定，优于贝塞尔曲线。
2. **交互范式**：点柱连线（黄色高亮 pending）、拖动元件导线跟随、双击电表读数、Delete 删件/删线、导线三色可选、示例电路一键载入。
3. **剖视教学**：`.casing` 外壳剖视时变透明，`.inner` 露出碳棒/锌筒/灯丝/线圈/电阻丝并带中文标注，是本实验室的亮点。
4. **错误接法即时反馈**：电流表并联、电压表串干路、滑变同上短路/同下不可调、电源短路，均有状态栏告警。
5. **可维护性**：求解器纯计算零 UI 依赖；器材定义（TYPES）与场景渲染分离；2D 与 3D 共用同一份 `comps/wires/solved` 状态。

### 2.2 设计问题（按严重度）

#### D1【中】2D 场景耦合 3D 遗留代码，与"回归 2D"的目标相悖
- 场景文件顶部直接 `import { createLabRenderer } from '../lab3d/three-render.js'`、`renderIcon/SOLID_TYPES` from `solidEquipment.js`；顶栏保留「🧊 3D 实验台」切换按钮；`view3d` 状态、3D 读数浮层、3D 操作条、3D 图标离屏渲染、整套 3D 回调转发（`handlersRef`/`labApiRef`/`onCompMove/onWireConnect/...`）都挂在 2D 组件里。
- 3D 遗留代码规模：`lab3d` 6 文件 4535 行、`sandbox3d` 20 文件 2176 行、`simple3d` 3 文件 1101 行；其中 `solidEquipment.js`（1879 行）、`three-render.js`（1578 行）只服务 3D。
- **影响**：首屏/打包体积被 3D 依赖（three、drei、fiber）拖累；2D 维护时需要绕开两套回调；继续在 2D 上迭代会反复踩到 3D 分支。

#### D2【中】元件库图标与桌面器材外形不一致
- 元件库小图标混用：电池/灯泡/开关/电表/滑变/电机/保险丝/电阻箱/万用表用实拍 `_c.png`，定值电阻、二极管、测电笔、验电器、市电、继电器用手绘迷你 SVG。
- 同一器材在库里是一套画法、拖到桌面是另一套画法，识别连续性差；手绘迷你图的比例、配色与实拍器材不统一。

#### D3【轻】画布与交互细节
- 导线命中区 18px 宽、可见线 5px，短线/交叉线处容易误选；2D 下没有"接线柱就近吸附"，必须精确点中 20×20 的柱帽。
- 元件拖出画布允许 −10px 出界，部分接线柱会落到可视区外，难以找回。
- 状态栏 `circuitStatus` 只统计第一只灯泡/变阻器/电流表/电压表/保险丝/继电器，多件同类器材时读数不全。
- 无撤销（Ctrl+Z）；删除导线/元件不可逆；示例电路每次 `loadDemo` 直接清空桌面，不二次确认。
- 电能表、焦耳管的累计状态（`meterKwhRef`/`jouleHeatRef`）在清空桌面后不复位，下次拖入同 id 器材可能残留旧数据（uid 递增降低了概率，但仍是隐患）。

### 3.4 求解器物理逻辑核对结果

**已正确（有测试覆盖）：**
- MNA 节点法 + 并查集等电位归并；滑变 tl/tr 金属杆等电位合并正确。
- 串/并联电流、电压分配；电表内阻（A=0.01Ω、V=10MΩ）分流分压影响符合预期。
- 二极管分段线性迭代（截止/导通自动收敛）；继电器吸合/释放状态迭代；保险丝过流熔断并持久断开。
- 电池端电压 U=E−Ir，短路时端电压塌到 0；伏安法内接/外接系统误差判定与偏差百分比。
- 滑变四种接法（左接/右接/全电阻丝/金属杆短路）判定与等效电阻。

**存在的物理/逻辑问题：**

#### P1【高】电动机按纯电阻建模，功率与发热混淆
- `motor` 注入恒定 4Ω 电阻，`_P=I²·4` 全部算成热功率；真实电动机电能大部分转化为机械能，铜耗只是小部分。当前模型下电机越转越"热"，物理方向错误，初中讲"电动机能量转化"时会误导。

#### P2【高】220V 家庭电路缺少安全建模，误接后果失真
- 市电 220V 直连定值电阻 15Ω → 14.5A；直连灯泡 5Ω → 43A；保险丝 0.5A 会熔断，但电机 4Ω、LED 等支路在 220V 下电流远超器件承受能力，求解器只在电源侧报短路（>15A），**器件本身无过载/烧毁保护**。
- 家庭电路规则未建模：开关必须接火线、螺口灯头螺旋套接零线、插座左零右火、漏电保护；当前任意接都能"工作"。
- 市电按直流等效，无交流相位，电能表/保险丝的有效值判定语义不严谨。

#### P3【中】灯泡为恒定电阻，未建模灯丝温度效应
- 真实灯丝冷态电阻小、热态电阻大，I-U 曲线非线性；当前 `BULB_R=5Ω` 恒定，亮度只由 `P=I²R` 换算，无法呈现"开灯瞬间冲击电流""灯丝越热电阻越大"等现象。项目内已有 `BulbIVCurveScene` 非线性模型，未回灌到本实验室。

#### P4【中】短路/过载判定阈值偏经验，边界场景可能误判
- 电池短路判据 `|I|>1.2A`、市电 `>15A`，是电流硬阈值而非"负载电阻趋近 0"的拓扑判定；高阻负载大电流（如小电阻直接接 220V）可能漏报器件过载。
- `sharesPair` 注释自承是"简化判定：任两端子同网即视为同节点对"，电流表并联/电压表串联检测在复杂并联拓扑下可能误报或漏报。

#### P5【中】导线电流叶传播在含环拓扑下残留置 0
- `computeWireCurrents` 靠叶子节点 KCL 传播，成环导线的环内电流无法分解，残留一律置 0；导致环流支路的导线电流动画、热色分级不真实（有测试盲区：未覆盖多环并联）。

#### P6【轻】电表/元件状态与标定细节
- 电流表量程柱 `meterRangeTap` 只认 full/mid，若两柱同时接线，优先 full，无"两柱同接"提示。
- 多用电表 Ω 档测带电外电路无联锁保护提示；电压档默认量程 15V，与入门 3V 档不一致。
- 电池/市电 `_I` 带符号、读数层取绝对值，反向接线只靠 `_rev` 黄色提示，未阻断反向测量。

#### P7【轻】测试覆盖盲区
- 现有测试未覆盖：多环并联导线电流、220V 下器件过载、灯泡非线性、电机反电动势、电能表计量口径、验电器/测电笔在直流回路的边界表现；2D 场景组件本身（拖拽、连线、读数浮层）无组件级测试。

2. 顶栏移除「📐 平面画布 / 🧊 3D 实验台」切换按钮；确认 `App.jsx` 不再经本场景进入 3D。
3. 暂时**不删除** `lab3d/`、`sandbox3d/`、`simple3d/` 目录与 three 依赖（避免误伤其他场景），先在本场景解耦；待 2D 验收稳定后，再评估整包摘除 three 依赖与归档目录。
4. 回归：`npm run test:run` 全绿；`npm run build` 成功；手动拖一套串/并联电路核对导线跟随与读数。

### P1｜修正物理模型硬伤（对应 P1、P3、P2 核心）

| 序号 | 事项 | 落点 | 验收标准 |
